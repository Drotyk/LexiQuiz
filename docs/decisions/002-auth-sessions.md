# ADR 002: Hybrid JWT Authentication & Session Revocation

- **Статус**: Прийнято (Accepted)
- **Дата**: 2026-08-06

## Контекст

Необхідно було забезпечити безпечну аутентифікацію користувачів, стійкість до XSS та CSRF атак, а також можливість виходу з усіх пристроїв або відкликання конкретної сесії.

## Рішення

Впроваджено гібридний підхід:
1. **Access Token**: JWT токен з коротким терміном дії (15 хв). Зберігається в оперативній пам'яті фронтенду.
2. **Refresh Token**: Довгоживучий токен (7 днів). Передається виключно через `httpOnly`, `sameSite=lax` cookie.
3. **UserSession Table**: Хешоване значення refresh токена зберігається у таблиці `user_sessions` у базе даних PostgreSQL разом із браузерним User-Agent та IP-адресою.

## Наслідки

### Позитивні:
- У разі витоку Access Token зловмисник отримує доступ лише на 15 хвилин.
- Захист від XSS (завдяки `httpOnly` cookie для refresh token).
- Користувач може переглядати список своїх активних сесій та відкликати їх у будь-який момент.

### Негативні / Ризики:
- Запит оновлення токена (`/auth/refresh`) вимагає звернення до бази даних для перевірки статусу сесії.
